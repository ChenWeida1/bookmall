# 纸间书店（BookMall）接口文档

| 项目   | 内容                                   |
| ---- | ------------------------------------ |
| 文档版本 | V2.0                                 |
| 编写日期 | 2026-10-09                           |
| 依据   | 《需求规格说明书》V1.0（变更记录至 V1.1）第 3、4、5、7 章 |
| 读者   | 前端、后端、测试                             |

本文档描述当前版本（含第六期）已确定的 HTTP 接口。路径与说明书第 4 章一致。真实支付、退款、物流、地址、优惠、评价、全部已读仍不在范围内。第六期增加管理员新增图书、图书内容文档、百度百科查询与引进，以及客服用智谱补写缺失梗概。

示例里的用户、图书与金额只用于说明字段，不是初始化种子数据。验收脚本中的账号 `demo_user` / `demo123456` 可直接用于注册与登录示例。

## 1. 概述

浏览器中的前端只访问 API 网关。网关负责路由、CORS 与对外 JWT 鉴权，再转发到业务服务。业务服务对受保护接口同样校验 JWT，避免调用方绕过网关直连。

| 服务                    | 职责         | 地址                      |
| --------------------- | ---------- | ----------------------- |
| bookmall-gateway      | 对外入口       | `http://localhost:8080` |
| bookmall-user         | 注册、登录、当前用户 | `http://localhost:8081` |
| bookmall-catalog      | 分类、图书、库存   | `http://localhost:8082` |
| bookmall-order        | 购物车、订单     | `http://localhost:8083` |
| bookmall-notification | 站内通知       | `http://localhost:8084` |

对外基址：`http://localhost:8080`。下文路径都相对于该基址。网关按原路径转发，服务内部路径与对外路径相同。

| 外部路径                              | 转发目标       |
| --------------------------------- | ---------- |
| `/api/users/**`                   | 用户服务 :8081 |
| `/api/categories`、`/api/books/**` | 图书服务 :8082 |
| `/api/admin/orders/**` | 订单服务 :8083 |
| `/api/admin/notifications/**` | 通知服务 :8084 |
| `/api/admin/**` | 图书服务 :8082 |
| `/api/cart/**`、`/api/orders/**`   | 订单服务 :8083 |
| `/api/notifications/**`           | 通知服务 :8084 |
| `/internal/**`                    | 不转发        |

内部接口由订单服务直连目标服务，不经过网关，也不对公网暴露：

| 方法   | 路径                                  | 调用方  | 目标         |
| ---- | ----------------------------------- | ---- | ---------- |
| POST | `/internal/books/{id}/stock/deduct` | 订单服务 | 图书服务 :8082 |
| POST | `/internal/books/{id}/stock/restore` | 订单服务 | 图书服务 :8082 |
| POST | `/internal/books/{id}/stock/restore-qty` | 订单服务 | 图书服务 :8082 |
| POST | `/internal/notifications`           | 运维补发 | 通知服务 :8084 |

第二版站内通知主路径为 RabbitMQ；`/internal/notifications` 保留作补发。隔离方式：网关不路由 `/internal/**`，并且 8081–8084 不对公网开放。内部库存接口不校验用户 JWT。扣库存请求里的 `token` 只用来保证同一笔扣减和回补只生效一次；订单取消使用 `restore-qty` 按数量还库存。

## 2. 通用约定

### 2.1 统一响应体

全部对外接口与内部接口都使用同一 JSON 包络。编码 UTF-8，响应头 `Content-Type: application/json; charset=UTF-8`。

```json
{
  "code": 0,
  "message": "ok",
  "data": {}
}
```

| 字段      | 类型                    | 说明                                        |
| ------- | --------------------- | ----------------------------------------- |
| code    | number                | `0` 表示成功；非 0 表示失败                         |
| message | string                | 成功时固定为 `ok`；失败时为可直接展示的中文                  |
| data    | object / array / null | 成功时为业务数据；失败时多数为 `null`。库存不足等需要结构化明细时见具体接口 |

成功的 HTTP 状态码统一为 **200**，包含注册、登录、创建订单、删除。失败时 HTTP 状态与 `code` 同时有效：HTTP 状态区分大类，`code` 区分原因，`message` 用于展示。响应不包含堆栈、SQL 或内部异常类名。

未定义的请求字段一律忽略。各接口另有说明的字段除外。

### 2.2 HTTP 状态

| HTTP | 场景                                                      |
| ---- | ------------------------------------------------------- |
| 200  | 成功                                                      |
| 400  | 参数不合法，或可预期的业务失败（用户名已存在、用户名或密码错误、购物车为空、库存不足、图书未上架、数量不合法） |
| 401  | 未登录，或 Token 缺失、格式错误、签名错误、过期                             |
| 403  | 已登录但无权限。第一版查看他人订单、购物车条目、通知时不返回 403，见 2.6                |
| 404  | 资源不存在                                                   |
| 500  | 未预期错误                                                   |
| 503  | 客服未配置（50301），或外部书目、内容库暂时不可用（50302）       |

登录失败属于可预期业务错误，HTTP 为 400，不使用 401。401 只表示访问受保护接口时凭证无效。

### 2.3 鉴权

公开接口：注册、登录、分类列表、图书列表、图书详情。这些接口不读取 `Authorization`。请求里带有无效 Token 时，公开接口仍然按匿名访问处理。

其余业务接口必须携带：

```http
Authorization: Bearer <token>
```

`Bearer` 与 Token 之间有一个空格。Token 是登录或注册返回的 JWT 本体，不含 `Bearer ` 前缀。缺失、不是 Bearer 方案、签名错误或过期，均返回 401。

| 项     | 约定                               |
| ----- | -------------------------------- |
| 算法与密钥 | 各服务使用同一套可配置 JWT 密钥               |
| 有效期   | 签发后 24 小时                        |
| 续期    | 调用业务接口不延长有效期；第一版没有刷新接口           |
| 密码    | 只出现在注册、登录的请求体中。任何响应都不返回明文密码或密码哈希 |

受保护接口的 401 响应：

```json
{
  "code": 40100,
  "message": "未登录或登录已失效",
  "data": null
}
```

### 2.4 字段与格式

JSON 使用驼峰命名。数据库列为下划线命名，对应关系如下。

| 数据库          | JSON        |
| ------------ | ----------- |
| cover_url    | coverUrl    |
| category_id  | categoryId  |
| order_no     | orderNo     |
| total_amount | totalAmount |
| unit_price   | unitPrice   |
| book_title   | bookTitle   |
| user_id      | userId      |
| read_flag    | read        |
| created_at   | createdAt   |

| 种类     | 约定                                                                                             |
| ------ | ---------------------------------------------------------------------------------------------- |
| 主键与数量  | JSON 数字。第一版主键处于 JavaScript 安全整数范围内                                                             |
| 金额     | 人民币「元」。JSON **字符串**，固定两位小数，例如 `"39.80"`。不含货币符号。服务端按十进制 `decimal(10,2)` 计算，舍入模式 HALF_UP。不用二进制浮点 |
| 时间     | ISO-8601 UTC，格式 `yyyy-MM-ddTHH:mm:ssZ`，例如 `2026-10-09T04:00:00Z`。不返回本地时区偏移                     |
| 布尔     | `true` / `false`                                                                               |
| 图书上架状态 | `ON_SALE`（可售）、`OFF_SALE`（不可售）                                                                  |
| 订单状态   | `PENDING_PAY` 待支付 / `PAID` 已支付 / `CANCELLED` 已取消。不做真实支付。                                  |
| 空字符串   | 请求中的可选文本会先去掉首尾空白；空白视为未传                                                                        |

小计与合计不单独落库的，按「单价 × 数量」用十进制算出后再格式化为两位小数字符串。

### 2.5 分页

图书列表、我的订单、通知列表使用同一组分页参数。

| 参数   | 位置    | 类型     | 必填 | 说明                   |
| ---- | ----- | ------ | -- | -------------------- |
| page | query | number | 否  | 页码，从 1 开始，默认 `1`     |
| size | query | number | 否  | 每页条数，默认 `10`，允许 1–50 |

`page` 小于 1，或 `size` 不在 1–50，返回 HTTP 400、`code` 40001。超过末页时 HTTP 200，`items` 为空数组，`total` 仍为总条数。

```json
{
  "page": 1,
  "size": 10,
  "total": 0,
  "items": []
}
```

| 字段    | 类型     | 说明       |
| ----- | ------ | -------- |
| page  | number | 当前页码     |
| size  | number | 本页请求的条数  |
| total | number | 符合条件的总条数 |
| items | array  | 当前页数据    |

分类列表与购物车不分页。订单与通知的分页是接口约定：说明书要求订单、通知按创建时间倒序，分页参数与图书列表对齐，避免一次返回全部历史。

### 2.6 资源归属

用户只能读取和修改自己的购物车、订单、通知。查询条件同时包含资源 ID 与当前用户 ID。

资源不存在，或资源属于其他用户时，统一返回 HTTP 404、`code` 40400。两种情况的 `message` 相同，响应不表明该资源是否存在。说明书允许此场景使用 403 或 404；本文档固定为 404。

| 资源    | message  |
| ----- | -------- |
| 订单    | 订单不存在    |
| 购物车条目 | 购物车条目不存在 |
| 通知    | 通知不存在    |
| 图书    | 图书不存在    |

客服历史没有单条查询。列表只含当前用户的消息，其他用户的对话不会出现。

### 2.7 未预期错误

HTTP 500：

```json
{
  "code": 50000,
  "message": "服务器内部错误",
  "data": null
}
```

## 3. 错误码

| code  | HTTP | message 示例 | 说明                                        |
| ----- | ---- | ---------- | ----------------------------------------- |
| 0     | 200  | ok         | 成功                                        |
| 40001 | 400  | 参数不合法      | 缺字段、长度、类型、分页超出范围                          |
| 40002 | 400  | 用户名已存在     | 注册重名                                      |
| 40003 | 400  | 用户名或密码错误   | 登录失败，不区分是用户名还是密码                          |
| 40004 | 400  | 图书未上架      | 图书存在且状态不是 `ON_SALE`                       |
| 40005 | 400  | 购物车为空      | 下单时当前用户没有可结算条目                            |
| 40006 | 400  | 库存不足       | 加购、改数量或下单时数量超过库存。下单时 `data.items` 列出不足的图书 |
| 40007 | 400  | 数量不合法      | 数量不是允许的整数                                 |
| 40100 | 401  | 未登录或登录已失效  | Token 缺失或无效                               |
| 40008 | 400  | 订单状态不允许取消 / 不允许支付 | 取消或支付非 `PENDING_PAY` 订单                    |
| 40300 | 403  | 无权限        | 非管理员调用管理端接口；私有资源越权仍按 2.6 返回 404          |
| 40400 | 404  | 图书不存在      | 资源不存在，或私有资源不属于当前用户                        |
| 50000 | 500  | 服务器内部错误    | 未预期错误                                     |
| 50301 | 503  | 客服未配置      | 开发、测试、生产都一样：没配置模型密钥时提问或生成梗概       |
| 50302 | 503  | 外部书目或内容库暂时不可用 | 百科连不上，或显式保存梗概时 MongoDB 不可用。图书详情和下单仍成功 |

参数不合法时，`message` 写明具体原因，例如「用户名长度须为 3–20 个字符」。下表为注册与登录常用文案。

| 场景           | message          |
| ------------ | ---------------- |
| 用户名长度不在 3–20 | 用户名长度须为 3–20 个字符 |
| 用户名含空白       | 用户名不能包含空白字符      |
| 密码长度不在 6–32  | 密码长度须为 6–32 个字符  |
| 昵称超过 32      | 昵称长度不能超过 32 个字符  |
| 缺少用户名或密码     | 用户名和密码不能为空       |

## 4. 公开接口

### 4.1 注册

| 项目  | 内容                              |
| --- | ------------------------------- |
| 方法  | POST                            |
| 路径  | `/api/users/register`           |
| 鉴权  | 否                               |
| 优先级 | P0                              |
| 说明  | 创建读者账号。成功后返回 JWT 与用户基本信息，并视为已登录 |

**请求头**

| 头            | 必填 | 说明                 |
| ------------ | -- | ------------------ |
| Content-Type | 是  | `application/json` |

**请求体**

| 参数       | 位置   | 类型     | 必填 | 约束                                   | 说明                     |
| -------- | ---- | ------ | -- | ------------------------------------ | ---------------------- |
| username | body | string | 是  | 去掉首尾空白后 3–20 个字符，中间不能有空白，系统内唯一，区分大小写 | 用户名                    |
| password | body | string | 是  | 6–32 个字符，首尾空格计入长度，服务端只存哈希            | 密码                     |
| nickname | body | string | 否  | 去掉首尾空白后 1–32 个字符                     | 昵称。省略、`null` 或空白时等于用户名 |


```json
{
  "username": "demo_user",
  "password": "demo123456",
  "nickname": "纸间读者"
}
```

**成功响应** HTTP 200

| 字段            | 类型     | 说明                            |
| ------------- | ------ | ----------------------------- |
| token         | string | JWT 本体                        |
| tokenType     | string | 固定 `Bearer`                   |
| expiresAt     | string | 过期时间，ISO-8601 UTC，签发时刻加 24 小时 |
| user.id       | number | 用户 ID                         |
| user.username | string | 用户名                           |
| user.nickname | string | 昵称                            |

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.example.signature",
    "tokenType": "Bearer",
    "expiresAt": "2026-10-10T04:00:00Z",
    "user": {
      "id": 1,
      "username": "demo_user",
      "nickname": "纸间读者"
    }
  }
}
```

**失败响应**

用户名已存在，HTTP 400：

```json
{
  "code": 40002,
  "message": "用户名已存在",
  "data": null
}
```

参数不合法，HTTP 400：

```json
{
  "code": 40001,
  "message": "用户名长度须为 3–20 个字符",
  "data": null
}
```

### 4.2 登录

| 项目  | 内容                   |
| --- | -------------------- |
| 方法  | POST                 |
| 路径  | `/api/users/login`   |
| 鉴权  | 否                    |
| 优先级 | P0                   |
| 说明  | 校验用户名与密码，成功后签发新的 JWT |

**请求头**

| 头            | 必填 | 说明                 |
| ------------ | -- | ------------------ |
| Content-Type | 是  | `application/json` |

**请求体**

| 参数       | 位置   | 类型     | 必填 | 约束       | 说明  |
| -------- | ---- | ------ | -- | -------- | --- |
| username | body | string | 是  | 与注册规则相同  | 用户名 |
| password | body | string | 是  | 6–32 个字符 | 密码  |

```json
{
  "username": "demo_user",
  "password": "demo123456"
}
```

**成功响应** HTTP 200

响应体与注册成功相同：`token`、`tokenType`、`expiresAt`、`user`（`id`、`username`、`nickname`）。每次登录签发新 Token。

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.example.signature",
    "tokenType": "Bearer",
    "expiresAt": "2026-10-10T04:00:00Z",
    "user": {
      "id": 1,
      "username": "demo_user",
      "nickname": "纸间读者"
    }
  }
}
```

**失败响应**

用户名或密码错误，HTTP 400。不存在的用户名、错误的密码使用同一 `code` 与同一 `message`。

```json
{
  "code": 40003,
  "message": "用户名或密码错误",
  "data": null
}
```

参数不合法（例如密码长度不对），HTTP 400：

```json
{
  "code": 40001,
  "message": "密码长度须为 6–32 个字符",
  "data": null
}
```

### 4.3 分类列表

| 项目  | 内容                               |
| --- | -------------------------------- |
| 方法  | GET                              |
| 路径  | `/api/categories`                |
| 鉴权  | 否                                |
| 优先级 | P0                               |
| 说明  | 返回全部图书分类。第一版分类来自初始化数据，至少 3 个。不分页 |

**请求头**

无必填请求头。

**参数**

无路径参数、查询参数、请求体。

**成功响应** HTTP 200

`data` 为数组，按 `id` 升序。

| 字段   | 类型     | 说明        |
| ---- | ------ | --------- |
| id   | number | 分类 ID     |
| name | string | 分类名，最长 32 |

```json
{
  "code": 0,
  "message": "ok",
  "data": [
    { "id": 1, "name": "文学" },
    { "id": 2, "name": "技术" },
    { "id": 3, "name": "生活" }
  ]
}
```

没有分类时 `data` 为 `[]`，HTTP 仍为 200。

### 4.4 图书列表

| 项目  | 内容                                                                 |
| --- | ------------------------------------------------------------------ |
| 方法  | GET                                                                |
| 路径  | `/api/books`                                                       |

### 5.6 创建订单

| 项目  | 内容                                                     |
| --- | ------------------------------------------------------ |
| 方法  | POST                                                   |
| 路径  | `/api/orders`                                          |
| 鉴权  | 是                                                      |
| 优先级 | P0                                                     |
| 说明  | 结算勾选的购物车条目；省略 `itemIds` 时结算全部。成功后状态为 `PENDING_PAY`，库存已扣减，已结算行从购物车删除，并尝试生成站内通知 |

**请求头**

| 头             | 必填 | 说明               |
| ------------- | -- | ---------------- |
| Authorization | 是  | `Bearer <token>` |

无路径参数与查询参数。请求体可省略。`itemIds` 为购物车条目主键数组时只结算这些行；省略、`null` 或空对象 `{}` 结算全部。空数组返回 HTTP 400、`code` 40001、`message`「请选择要结算的商品」。`itemIds` 不是数组、含非正整数，或含有不属于当前用户的条目，返回 40001。其他未定义字段忽略。

请求体示例：

```json
{ "itemIds": [12, 15] }
```

**处理顺序**

1. `itemIds` 不合法或为空数组：返回 40001。不扣库存，不创建订单。
2. 未指定 `itemIds` 且当前用户购物车没有任何条目：返回 40005。不扣库存，不创建订单。
3. 订单服务读取每本图书的当前信息。
4. 有图书不存在：整单失败，HTTP 404。不扣库存。
5. 有图书不是 `ON_SALE`：整单失败，HTTP 400、`code` 40004。不扣库存。
6. 有图书库存小于购买数量：整单失败，HTTP 400、`code` 40006，`data.items` 列出全部库存不足的图书。不扣库存。
7. 上述校验都通过后，按购物车条目顺序调用 `POST /internal/books/{id}/stock/deduct`。
8. 全部扣减成功后，写入订单与明细。明细保存书名、成交单价快照。状态为 `PENDING_PAY`。然后只删除本次结算的购物车条目。同时投递支付超时消息，投递失败不回滚订单。
9. 同步调用 `POST /internal/notifications`。通知失败或超时（建议超时 1 秒）时，订单接口仍然成功。订单服务记录错误日志，至少包含 `orderNo`、`userId`、`totalAmount` 与失败原因，便于以后补发。

同一响应只返回一种业务错误。检查顺序为：`itemIds`、空购物车、图书不存在、未上架、库存不足。同一类问题一次列全，例如多本库存不足时全部出现在 `data.items` 中。

订单号全局唯一，长度不超过 32。格式为 UTC 时间 `yyyyMMddHHmmss` 再接 6 位大写字母或数字，例如 `20261009040000A1B2C3`。发生碰撞时重新生成。

商品件数 `itemCount` 等于各明细 `quantity` 之和，不是明细行数。

**并发与补偿**

单本扣减在图书服务内原子完成：仅当 `stock >= quantity` 时扣减，库存不会变成负数。同一用户的下单在订单库事务锁上串行，避免一次购物车生成两笔订单。

校验阶段发现库存不足时整单失败，此时还没有扣减，也不会产生订单。

扣减请求带订单服务生成的 `token`。同一 token 只扣一次。扣减前先把占用写入订单库的 `stock_hold`。若后续某一本扣减失败、写订单失败或调用超时：停止后续扣减，不创建订单，不清空购物车，并按已尝试的 token 调用 `POST /internal/books/{id}/stock/restore`。该回补同样按 token 只执行一次；令牌不存在表示扣减没有落地，回补直接成功。回补失败时订单接口返回 50000，占用记录保留，下次下单会继续回补。进程在扣减和写订单之间中断时，下次该用户下单先按 `stock_hold` 回补，再结算当前购物车。订单服务记录错误日志，至少包含 `userId`、`bookId`、`quantity` 与原因。可预期的库存不足仍发生在扣减之前。

**成功响应** HTTP 200

返回订单头与明细。通知是否写入不改变本响应；调用方到通知列表查看消息。

| 字段                | 类型     | 说明                |
| ----------------- | ------ | ----------------- |
| id                | number | 订单主键，用于订单详情路径     |
| orderNo           | string | 订单号               |
| totalAmount       | string | 总金额               |
| status            | string | `PENDING_PAY`       |
| createdAt         | string | 创建时间，ISO-8601 UTC |
| itemCount         | number | 商品件数，数量之和         |
| items             | array  | 明细                |

## 6. 内部接口

内部接口使用第 2 章的统一响应体。调用方是订单服务，不携带用户的 `Authorization`。基址是目标服务本身，不是网关。

| 调用   | 完整地址                                                          |
| ---- | ------------------------------------------------------------- |
| 扣库存  | `POST http://localhost:8082/internal/books/{id}/stock/deduct` |
| 回补库存 | `POST http://localhost:8082/internal/books/{id}/stock/restore` |
| 创建通知 | `POST http://localhost:8084/internal/notifications`           |

订单服务在计价与校验库存时，还可以直连 `GET http://localhost:8082/api/books/{id}`。这是已有的公开接口，不是新的内部接口。

### 8.3 通知与 RabbitMQ

- 下单成功：订单服务向交换机 `bookmall.notification` 投递消息，路由键 `notification.create`。
- 通知服务消费后写入 `notification` 表；`biz_key` 唯一，重复投递不产生第二条。
- 典型 `biz_key`：`ORDER_CREATED:{orderNo}`、`ORDER_PAID:{orderNo}`、`ORDER_CANCELLED:{orderNo}`。
- 投递失败不影响订单事务；通知最终一致。
- 参数不合法的消息确认后丢弃。数据库等瞬时失败最多重试 3 次，然后进入死信队列 `bookmall.notification.create.dlq`。
- 若本机已经存在不带死信参数的 `bookmall.notification.create`，启动前需删除该队列，否则声明会失败。
- `POST /internal/notifications` 仍可用于运维补发，请求体可带 `bizKey`。

### 8.4 Redis 缓存（图书服务）

- 缓存分类列表与在售图书分页列表，TTL 约 60 秒。
- Key 前缀：`bookmall:catalog:categories`、`bookmall:catalog:books:...`。
- 管理端改书、库存扣减/回补后删除相关 key。
- Redis 短暂不可用时降级读库，不返回 500。

## 9. 第四版：订单运营

成功响应仍是 `code = 0`、`message = ok`。管理接口都要求管理员角色，普通读者返回 HTTP 403、`code` 40300。

### 9.1 管理端订单列表

| 项 | 值 |
| --- | --- |
| 方法 | `GET` |
| 路径 | `/api/admin/orders` |
| 鉴权 | 管理员 |
| 说明 | 分页返回全部用户的订单摘要。可选查询参数 `status`，取值与 5.7 相同，非法值 40001。 |

`data.items` 字段：`id`、`userId`、`orderNo`、`totalAmount`、`status`、`createdAt`。不提供管理员支付或取消。

### 9.2 管理端订单详情

| 项 | 值 |
| --- | --- |
| 方法 | `GET` |
| 路径 | `/api/admin/orders/{id}` |
| 鉴权 | 管理员 |
| 说明 | 任意用户的订单详情，结构与 `GET /api/orders/{id}` 相同，并额外返回 `userId`。不存在时 40400。 |

### 9.3 死信查看与重投

两条死信队列都没有常驻消费者。`GET` 用 `basicGet` 读出队头后重新入队，不确认。`POST` 处理最早的一条。

| 方法 | 路径 | 队列 |
| --- | --- | --- |
| GET | `/api/admin/notifications/dead-letters` | `bookmall.notification.create.dlq` |
| POST | `/api/admin/notifications/dead-letters` | 同上 |
| GET | `/api/admin/orders/dead-letters` | `bookmall.order.pay.timeout.dlq` |
| POST | `/api/admin/orders/dead-letters` | 同上 |

`GET` 的 `data`：`queue`、`count`、`head`。`head` 为队头 JSON，空队列时为 `null`。通知消息含 `bizKey`，超时消息含 `orderId`。

`POST` 请求体：

```json
{ "action": "replay" }
```

`action` 为 `replay` 或 `discard`。通知重投发回交换机 `bookmall.notification`、路由键 `notification.create`，由现有消费者按 `bizKey` 幂等入库。超时重投发回交换机 `bookmall.order.pay`、路由键 `pay.timeout`，不再进入延迟队列；仍是待支付才会取消并还库存。队列为空或 `action` 非法时返回 40001。

网关必须把 `/api/admin/orders/**`、`/api/admin/notifications/**` 写在 `/api/admin/**` 之前，否则会进图书服务。

## 10. 第五期：全局事务、客服、追踪号

成功响应仍是 `code = 0`、`message = ok`。流式提问成功时响应体是 `text/event-stream`，不是这个 JSON 包络。提问在写出事件流之前失败（未登录、参数不合法、客服未配置）仍走统一包络。

### 10.1 下单全局事务

`POST /api/orders` 的扣库存和写订单在同一个 Seata AT 全局事务里。图书服务的扣库存本地事务通过 Feign 上的 XID 加入。写订单失败时 undo log 回滚库存，订单服务不再按令牌手工回补。

协调者使用文件注册，地址来自配置 `SEATA_ADDR`，默认 `127.0.0.1:8091`，不走 Nacos。协调者不可用时下单失败。取消订单和支付超时不在这个全局事务里。下单通知和支付超时消息在全局事务提交之后发出，失败只记日志。

### 10.2 客服历史

| 项 | 值 |
| --- | --- |
| 方法 | `GET` |
| 路径 | `/api/assistant/messages` |
| 鉴权 | 登录用户，只返回本人 |
| 分页 | `page`、`size`，规则同 2.5 |

`data.items` 按该页内时间从早到晚。第 1 页是最近的消息。字段：`id`、`role`（`user` / `assistant`）、`content`、`createdAt`。

### 10.3 客服提问

| 项 | 值 |
| --- | --- |
| 方法 | `POST` |
| 路径 | `/api/assistant/messages` |
| 鉴权 | 登录用户 |
| 成功响应 | `Content-Type: text/event-stream` |

请求体：

```json
{ "content": "有没有围城" }
```

`content` 去掉空白后为空，或超过 2000 字，返回 40001。没配置 `AI_API_KEY` 时返回 HTTP 503、`code` 50301、message「客服未配置」，并且不写入这条提问。

事件：

| event | data |
| --- | --- |
| delta | `{"text":"片段"}` |
| done | `{"content":"完整回复"}` |
| error | `{"message":"服务器内部错误"}` |

用户消息先入库。`done` 之前写入客服回复；连接中断则保存已经生成的文字。模型只接收最近 10 轮。工具只能查书，不能下单、支付或取消。

网关把该路径转到客服服务，响应超时 90 秒，并放行 `text/event-stream`。浏览器用 `fetch` 携带 `Authorization` 读取，不用 `EventSource`。

### 10.4 内部查书

| 项 | 值 |
| --- | --- |
| 方法 | `GET` |
| 路径 | `/internal/books/search` |
| 说明 | 只给客服服务直连。查询参数 `title`、`author`、`category` 都可空；三个都空时返回空列表。结果最多 8 本，包含下架书。 |

每条含 `id`、`title`、`author`、`price`、`stock`、`status`（`ON_SALE` / `OFF_SALE`）、`categoryId`、`categoryName`。网关不路由 `/internal/**`。

### 10.5 追踪号

网关、五个业务服务和客服的日志级别列包含 `traceId` 和 `spanId`。同一次下单或同一次提问使用同一个追踪号。本机和 Compose 的 Zipkin 在 `9411`。生产默认不导出；设置 `ZIPKIN_EXPORT_ENABLED=true` 且提供 `ZIPKIN_ENDPOINT` 才导出。

## 11. 第六期：新增图书、内容文档、百科

成功响应仍是 `code = 0`、`message = ok`。浏览器只走网关。`/internal/**` 仍不经过网关。

MongoDB 库 `bookmall_content`，集合 `book_content`。不可用时图书列表、详情里的价格库存和下单仍成功，只是没有梗概字段。显式保存内容失败时 HTTP 503、`code` 50302、message「内容库暂时不可用」。

### 11.1 新增图书

| 项 | 值 |
| --- | --- |
| 方法 | `POST` |
| 路径 | `/api/admin/books` |
| 鉴权 | 管理员。读者返回 40300 |

必填：`categoryId`、`title`、`author`、`price`、`stock`、`status`（`ON_SALE` / `OFF_SALE`）。可选：`coverUrl`、`description`、`isbn`、`synopsis`、`tags`。分类不存在、价格或库存为负、状态非法，返回 40001。成功 `data` 为图书详情。写入后清除在售列表缓存。

### 11.2 编辑内容

`PUT /api/admin/books/{id}/content`，管理员。正文：`synopsis`、`contents`、`excerpt`、`tags`、`authorBio`。书不存在返回 40400。来源记为 `ADMIN`。

`GET /api/books/{id}` 在原字段外，有文档时附带上述内容和 `source`。列表不加长文本。

### 11.3 百度百科

只在图书服务调用百科名片接口，超时 3 秒。`appid` 用公开示例 `379020`，放在服务端配置 `bookmall.baike.app-id`。

`GET /api/admin/books/external?q=`：命中一条词条。`data` 含 `lemmaId`、`title`、`author`、`synopsis`、`contents`、`url`、`source`、`inStore`，不含价格和库存。没有词条时 `data` 为 null。连不上时 50302、message「外部书目暂时不可用」。内容库写不进去时同样是 50302，message「内容库暂时不可用」。

`POST /api/admin/books/import`：`lemmaId`、`categoryId`、`price`、`stock`、`status`。同一 `lemmaId` 已引进返回 40001。须先搜索，否则 40001。

客服使用 `GET /internal/books/external?q=`，规则相同。

### 11.4 智谱补梗概

`POST /api/assistant/books/{id}/synopsis`，管理员。没有梗概时用已配置的 `AI_API_KEY` 写一段中文梗概，写入 Mongo，`source` 为 `ZHIPU`。没密钥时 50301，详情接口不因此失败。`source` 为 `ADMIN` 或 `BAIDU` 且已有梗概时不覆盖。

客服工具可按编号读梗概，并按书名或作者查外部书。外部书必须说明本店未上架，不得编造价格、库存或上下架。百科已有摘要时不调用智谱。百科没有摘要时，用智谱按书名和作者补一段，写入该词条，`source` 为 `ZHIPU`，结果标明本店未上架。工具不提供下单、支付或取消。
