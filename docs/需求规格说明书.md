## 1. 引言

### 1.1 编写目的

本文档用于明确「纸间书店」当前版本（含第二版增强）的业务范围、功能需求、非功能约束与验收标准，作为后续系统设计、开发、联调与验收的统一依据。

读者包括：产品/需求侧、后端开发、前端开发、测试，以及使用 Cursor Agent 协助开发的学习者本人。

### 1.2 项目背景

本项目是一个面向学习的 **Java 微服务 + 前后端完整示例**。目标不是做成商业电商，而是在真实业务主线上练会：

1. 用多个独立服务拆分业务；
2. 用网关统一入口与鉴权；
3. 完成「浏览 → 登录 → 加购 → 下单 → 通知」闭环；
4. 用 Cursor 按阶段完成一个可演示的完整项目。

### 1.3 术语与缩写

| 术语    | 说明                      |
| ----- | ----------------------- |
| 用户    | 可注册、登录并购买图书的读者账号        |
| 图书    | 可浏览、可加购、可下单的商品          |
| 购物车   | 用户待结算图书列表，按用户隔离         |
| 订单    | 用户一次结算产生的购买记录           |
| 库存    | 图书可售数量，下单时扣减            |
| JWT   | JSON Web Token，登录后的访问凭证 |
| 网关    | 统一对外 HTTP 入口，负责路由与鉴权    |
| 服务间调用 | 订单服务调用图书服务等内部接口         |
| 通知    | 下单成功后生成的站内消息            |

### 1.4 参考与约束

- 技术栈方向：Java 21、Spring Boot 3、Spring Cloud Gateway、Vue 3、PostgreSQL 16。
- 第一版优先保证本地可运行、主流程可演示。
- 不引入真实支付、物流、秒杀、复杂分布式事务中间件。

## 2. 总体描述

### 2.1 产品愿景

为学习微服务与全栈开发，提供一个边界清晰、可逐步扩展的在线书店系统：读者可浏览图书、管理购物车、完成下单并收到站内通知。

### 2.2 用户角色

| 角色       | 说明        | 第一版能力                   |
| -------- | --------- | ----------------------- |
| 游客       | 未登录访问者    | 浏览图书列表、查看图书详情           |
| 读者（登录用户） | 已注册并登录的账号 | 加购、改数量、下单、查看订单、查看通知     |
| 管理员      | 后台运营人员    | 第二版：图书上架/下架（可选改库存）；种子账号 `admin` |

### 2.3 业务范围

#### 2.3.1 范围内（In Scope）

1. 用户注册、登录、获取当前用户信息。
2. 图书分类、图书列表、图书详情。
3. 购物车增删改查。
4. 创建订单、查看我的订单、订单详情。
5. 下单时扣减库存。
6. 下单成功后产生站内通知，用户可查看通知列表。
7. 前端页面：首页/图书、详情、登录注册、购物车、订单、通知。
8. API 网关统一入口。

#### 2.3.2 范围外（Out of Scope）

以下内容明确不在第一版：

- 真实支付（微信/支付宝）、退款、发票
- 物流、收货地址管理、快递轨迹
- 优惠券、积分、会员等级
- 秒杀、拼团、评价/评分体系
- 后台管理端（图书/订单运营后台）
- 搜索引擎（Elasticsearch）、推荐算法
- Kubernetes、服务网格、全链路复杂监控
- Seata 等分布式事务框架
- 短信/邮件真实外发

### 2.4 系统上下文

外部使用者只有浏览器中的前端应用。前端只访问网关；网关转发到各业务服务。

```text
浏览器(Vue)
    │
    ▼
API 网关 (:8080)
    ├── 用户服务 (:8081)
    ├── 图书服务 (:8082)
    ├── 订单服务 (:8083) ──内部调用──► 图书服务
    └── 通知服务 (:8084)
```

### 2.5 假设与依赖

1. 开发与演示环境可运行 JDK 21、Node.js、Maven，并可通过 Docker 启动 PostgreSQL。
2. 第一版使用 PostgreSQL 16：一个实例、四个库（`bookmall_user`、`bookmall_book`、`bookmall_order`、`bookmall_notification`）。每个服务使用独立账号，只授权访问自己的库。不计划再切换其他数据库。
3. 第二版站内通知经 RabbitMQ 异步写入；订单服务只负责投递，通知服务消费并按 biz_key 幂等入库。内部 HTTP 补发接口可保留，不对公网暴露。
4. 第二版图书服务使用 Redis 缓存分类与在售列表（短 TTL）；管理端改书或库存变化后失效缓存。Redis 不可用时降级读库。
5. 所有受保护接口使用同一套 JWT 密钥与鉴权规则。

## 3. 功能需求

### 3.1 用例总览

| 编号    | 用例             | 主要角色  | 优先级 |
| ----- | -------------- | ----- | --- |
| UC-01 | 注册账号           | 游客    | P0  |
| UC-02 | 登录             | 游客    | P0  |
| UC-03 | 查看当前用户         | 读者    | P0  |
| UC-04 | 浏览图书列表         | 游客/读者 | P0  |
| UC-05 | 查看图书详情         | 游客/读者 | P0  |
| UC-06 | 加入购物车          | 读者    | P0  |
| UC-07 | 修改购物车数量 / 删除条目 | 读者    | P0  |
| UC-08 | 查看购物车          | 读者    | P0  |
| UC-09 | 提交订单           | 读者    | P0  |
| UC-10 | 查看我的订单 / 订单详情  | 读者    | P0  |
| UC-11 | 查看站内通知         | 读者    | P1  |
| UC-12 | 按分类筛选图书        | 游客/读者 | P1  |

### 3.2 用户与认证

#### FR-U-01 注册

- 输入：用户名、密码、昵称（可选）。
- 规则：
  - 用户名 3–20 字符，系统内唯一；
  - 密码 6–32 字符，服务端加密存储，禁止明文落库；
  - 昵称为空时默认等于用户名。
- 成功：返回 JWT 与用户基本信息，视为自动登录。
- 失败：用户名已存在、参数不合法时返回明确错误信息。

#### FR-U-02 登录

- 输入：用户名、密码。
- 成功：返回 JWT 与用户基本信息。
- 失败：用户名或密码错误时，不区分具体哪一项错误（统一提示）。

#### FR-U-03 当前用户

- 需要登录。
- 返回：用户 ID、用户名、昵称。
- Token 无效或过期：返回 401。

#### FR-U-04 鉴权规则

- 公开接口：注册、登录、图书列表、图书详情、分类列表。
- 其余业务接口：必须携带 `Authorization: Bearer <token>`。
- 网关负责对外鉴权；业务服务也应具备防护能力（防止绕过网关直连）。

### 3.3 图书与分类

#### FR-B-01 分类列表

- 返回全部图书分类（如文学、技术、生活等）。
- 第一版分类由初始化数据提供。

#### FR-B-02 图书列表

- 支持分页。
- 可选按分类筛选。
- 可选按书名关键字模糊查询（P1）。
- 列表字段至少包含：图书 ID、书名、作者、封面、价格、库存、分类名。

#### FR-B-03 图书详情

- 按图书 ID 查询。
- 不存在时返回 404 业务错误。
- 详情字段在列表字段基础上增加：简介、ISBN（可选）、上架状态。

#### FR-B-04 库存扣减（内部）

- 提供仅供内部调用的库存扣减接口。
- 输入：图书 ID、扣减数量。
- 规则：库存不足则失败，不得扣成负数。
- 成功后返回最新库存。

#### FR-B-05 初始化数据

- 系统首次启动应自动准备：
  - 不少于 3 个分类；
  - 不少于 8 本示例图书；
  - 每本图书库存 > 0。

### 3.4 购物车

#### FR-C-01 加入购物车

- 需要登录。
- 输入：图书 ID、数量（默认 1）。
- 规则：
  - 图书必须存在且可售；
  - 数量必须为正整数；
  - 同一用户同一图书合并数量，不新增重复行。
- 数量合计不得超过当前库存（可在加购或下单时校验；第一版要求**下单时强校验**，加购时建议校验）。

#### FR-C-02 修改数量

- 需要登录。
- 只能修改本人购物车条目。
- 数量改为 0 时视为删除该条目。

#### FR-C-03 删除条目

- 需要登录。
- 只能删除本人购物车条目。

#### FR-C-04 查看购物车

- 需要登录。
- 返回条目列表：图书信息快照（至少书名、单价、封面）、数量、小计。
- 同时返回应付合计金额。

### 3.5 订单

#### FR-O-01 创建订单

- 需要登录。
- 输入：购物车中勾选的条目，或“结算全部”（第一版可采用结算全部购物车）。
- 处理流程：
  1. 校验购物车非空；
  2. 校验每本图书库存充足；
  3. 扣减库存；
  4. 生成订单与订单明细；
  5. 清空已结算购物车条目；
  6. 触发下单成功通知。
- 订单状态：
  - `1`：已创建（CREATED，视为演示完成，无需支付）；
  - `2`：已取消（CANCELLED）。
- 失败时：不得产生“库存已扣但无订单”的脏状态；若实现上采用尽力而为，需在文档/日志中说明补偿策略。最低要求：**库存不足时整单失败**。

#### FR-O-02 我的订单列表

- 需要登录。
- 仅返回当前用户订单。
- 支持按创建时间倒序。
- 列表字段：订单号、总金额、状态、创建时间、商品件数。

#### FR-O-03 订单详情

- 需要登录。
- 只能查看本人订单。
- 包含订单头信息与明细列表（书名、单价、数量、小计）。

#### FR-O-04 订单号规则

- 订单号全局唯一，可读性优先（如时间戳 + 随机串），不要求符合外部支付规范。

#### FR-O-05 取消订单（第二版）

- 需要登录；仅本人可取消。
- 仅 `CREATED` 可取消；成功后状态为 `CANCELLED`，并按明细数量加回库存。
- 可投递取消站内通知（`biz_key=ORDER_CANCELLED:{订单号}`）。
- 已取消订单不可再次取消；他人订单或不存在按 404。

### 3.6 通知

#### FR-N-01 下单成功通知

- 订单创建成功后，为对应用户生成一条站内通知（第二版经 RabbitMQ，最终一致）。
- 通知内容示例：`您的订单 {订单号} 已创建成功，合计 ¥{金额}`。
- 幂等键：`ORDER_CREATED:{订单号}`。

#### FR-N-02 通知列表

- 需要登录。
- 仅返回当前用户通知，按时间倒序。
- 字段：通知 ID、标题/内容、是否已读、创建时间。

#### FR-N-03 标记已读（P1）

- 支持单条标记已读；可选支持全部已读。

### 3.7 前端功能需求

#### FR-F-01 页面清单

| 页面    | 说明           |
| ----- | ------------ |
| 首页/书城 | 分类筛选 + 图书列表  |
| 图书详情  | 展示详情，支持加入购物车 |
| 登录/注册 | 表单提交，成功后跳转   |
| 购物车   | 数量修改、删除、去结算  |
| 我的订单  | 订单列表与详情；可取消已创建订单 |
| 消息中心  | 通知列表         |
| 管理     | 管理员上架/下架图书（可选改库存） |

#### FR-F-02 交互要求

1. 未登录访问受保护操作时，引导至登录页。
2. Token 存于前端本地（如 localStorage），请求自动携带。
3. 接口错误需有可读提示（如库存不足、用户名已存在）。
4. 桌面端优先；移动端基本可用即可（不要求复杂自适应设计系统）。

#### FR-F-03 视觉基调（建议）

- 品牌名「纸间书店」在首屏应有明确识别。
- 风格偏阅读/书店氛围，避免常见 AI 模板感（如紫白渐变堆砌）。
- 第一版以功能完整优先，视觉可后续迭代。

## 4. 服务拆分与接口边界

### 4.1 服务清单

| 服务                    | 职责             | 建议端口 |
| --------------------- | -------------- | ---- |
| bookmall-gateway      | 路由、CORS、JWT 鉴权 | 8080 |

### 4.2 外部 API（经网关）

> 下列为逻辑接口清单，具体路径可在详细设计中微调，但语义不得偏离。

#### 用户服务

| 方法   | 路径                    | 鉴权 | 说明   |
| ---- | --------------------- | -- | ---- |
| POST | `/api/users/register` | 否  | 注册   |
| POST | `/api/users/login`    | 否  | 登录   |
| GET  | `/api/users/me`       | 是  | 当前用户 |

#### 图书服务

| 方法  | 路径                | 鉴权 | 说明          |
| --- | ----------------- | -- | ----------- |
| GET | `/api/categories` | 否  | 分类列表        |
| GET | `/api/books`      | 否  | 图书列表（分页/筛选） |
| GET | `/api/books/{id}` | 否  | 图书详情        |

#### 订单服务

| 方法     | 路径                     | 鉴权 | 说明    |
| ------ | ---------------------- | -- | ----- |
| GET    | `/api/cart`            | 是  | 查看购物车 |
| POST   | `/api/cart/items`      | 是  | 加入购物车 |
| PUT    | `/api/cart/items/{id}` | 是  | 修改数量  |
| DELETE | `/api/cart/items/{id}` | 是  | 删除条目  |
| POST   | `/api/orders`          | 是  | 创建订单  |
| GET    | `/api/orders`          | 是  | 我的订单  |
| GET    | `/api/orders/{id}`     | 是  | 订单详情  |

#### 通知服务

| 方法   | 路径                             | 鉴权 | 说明       |
| ---- | ------------------------------ | -- | -------- |
| GET  | `/api/notifications`           | 是  | 通知列表     |
| POST | `/api/notifications/{id}/read` | 是  | 标记已读（P1） |

### 4.3 内部接口

| 方法   | 路径                                  | 调用方  | 说明   |
| ---- | ----------------------------------- | ---- | ---- |
| POST | `/internal/books/{id}/stock/deduct` | 订单服务 | 扣库存  |
| POST | `/internal/notifications`           | 订单服务 | 创建通知 |

内部接口不得对公网暴露；第一版可通过网关不路由 `/internal/**` 实现隔离。

### 4.4 统一响应约定

```json
{
  "code": 0,
  "message": "ok",
  "data": {}
}
```

- `code = 0` 表示成功。
- 业务失败：`code` 非 0，`message` 为可读中文。
- HTTP 状态码建议：
  - 400 参数/业务可预期错误；
  - 401 未登录或 Token 失效；
  - 403 无权限（如查看他人订单）；
  - 404 资源不存在；
  - 500 未预期错误。

| created_at | timestamptz  | not null | 创建时间（UTC） |

### 5.5 数据隔离原则

- 使用 PostgreSQL。四个库与服务对应：`bookmall_user`（用户服务）、`bookmall_book`（图书服务）、`bookmall_order`（订单服务）、`bookmall_notification`（通知服务）。
- 每个服务使用独立账号，只授权自己的库。禁止跨服务直接访问对方数据库。
- 主键使用 `bigint generated by default as identity`。
- 时间字段使用 `timestamptz`，应用按 UTC 写入。
- 订单明细中的书名、单价必须落快照，避免图书信息变更影响历史订单展示。

## 6. 非功能需求

### 6.1 可用性与体验

- 本地一键或少量命令可启动全部服务与前端。
- 主流程操作反馈时间在本地环境下通常 < 2 秒。
- 关键错误信息对用户可读，不直接暴露堆栈。

### 6.2 安全性

- 密码加密存储（如 BCrypt）。
- JWT 密钥可配置，长度满足算法要求。
- 所有写操作与用户私有读操作必须鉴权。
- 用户只能访问自己的购物车、订单、通知。

### 6.3 可维护性

- 多模块 Maven 工程，模块边界清晰。
- 统一响应体与统一异常处理。
- 提供 README：如何启动、如何演示、默认账号/种子数据说明。

### 6.4 可测试性

- 至少覆盖：
  - 注册/登录成功与失败；
  - 库存不足下单失败；
  - 下单成功后订单可见、购物车已清空、通知已生成。
- 可用接口测试或集成测试完成，不强制 UI 自动化。

### 6.5 兼容性

- 后端：JDK 21。
- 前端：现代 Chromium 内核浏览器（Chrome / Edge 近两个大版本）。
- 第一版不要求 IE 或老旧移动浏览器。

### 6.6 性能（学习项目级别）

- 不做压测达标要求。
- 图书列表分页默认每页 10 条，避免一次返回过大。

## 7. 核心业务流程

### 7.1 下单主流程（P0）

```text
读者登录
  → 浏览图书并加入购物车
  → 打开购物车确认
  → 提交订单
  → 订单服务校验购物车与库存
  → 调用图书服务扣库存
  → 保存订单与明细
  → 清空已结算购物车
  → 调用通知服务创建消息
  → 前端展示下单成功，可进入订单/消息页
```

### 7.2 异常流程

| 场景 | 期望行为 |
| --- | --- |
| Token 缺失/过期 | 401，前端跳转登录 |
| 用户名重复注册 | 提示用户名已存在 |
| 图书不存在 | 提示图书不存在 |
| 库存不足 | 整单失败，提示哪些书库存不足（至少提示失败原因） |
| 查看他人订单 | 403 或 404（不泄露存在性亦可） |
| 通知服务暂时失败 | 订单仍应成功（P1 可接受）；需记录日志，后续可补发 |

## 8. 验收标准

第一版达到以下条件即可验收：

1. 网关、用户、图书、订单、通知、前端均可启动。
2. 游客可浏览图书列表与详情。
3. 新用户可注册并自动登录；老用户可登录。
4. 登录用户可加购、修改数量、删除购物车条目。
5. 登录用户可成功下单；订单列表与详情正确；对应图书库存减少。
6. 库存不足时下单失败，且不产生错误订单。
7. 下单成功后通知列表出现对应消息。
8. 未登录无法访问购物车/订单/通知接口。
9. 存在 README，说明启动步骤与演示路径。
