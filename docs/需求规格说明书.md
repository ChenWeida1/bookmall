## 1. 引言

### 1.1 编写目的

本文档用于明确「纸间书店」当前版本（含第二版增强）的业务范围、功能需求、非功能约束与验收标准，作为后续系统设计、开发、联调与验收的统一依据。

读者包括：产品/需求侧、后端开发、前端开发、测试，以及使用 Cursor Agent 协助开发的学习者本人。

### 1.2 项目背景

本项目是一个面向学习的 **Java 微服务 + 前后端完整示例**。目标不是做成商业电商，而是在真实业务主线上练会：

1. 用多个独立服务拆分业务；
2. 用网关统一入口与鉴权；
3. 完成「浏览 → 登录 → 加购 → 下单 → 通知」闭环；
4. 用 Cursor 按阶段完成一个可演示的完整项目。

### 1.3 术语与缩写

| 术语    | 说明                      |
| ----- | ----------------------- |
| 用户    | 可注册、登录并购买图书的读者账号        |
| 图书    | 可浏览、可加购、可下单的商品          |
| 购物车   | 用户待结算图书列表，按用户隔离         |
| 订单    | 用户一次结算产生的购买记录           |
| 库存    | 图书可售数量，下单时扣减            |
| JWT   | JSON Web Token，登录后的访问凭证 |
| 网关    | 统一对外 HTTP 入口，负责路由与鉴权    |
| 服务间调用 | 订单服务调用图书服务等内部接口         |
| 通知    | 下单成功后生成的站内消息            |

### 1.4 参考与约束

- 技术栈方向：Java 21、Spring Boot 3、Spring Cloud Gateway、Vue 3、PostgreSQL 16。
- 第一版优先保证本地可运行、主流程可演示。
- 不引入真实支付、物流、秒杀、复杂分布式事务中间件。

## 2. 总体描述

### 2.1 产品愿景

为学习微服务与全栈开发，提供一个边界清晰、可逐步扩展的在线书店系统：读者可浏览图书、管理购物车、完成下单并收到站内通知。

### 2.2 用户角色

| 角色       | 说明        | 第一版能力                   |
| -------- | --------- | ----------------------- |
| 游客       | 未登录访问者    | 浏览图书列表、查看图书详情           |
| 读者（登录用户） | 已注册并登录的账号 | 加购、改数量、下单、查看订单、查看通知     |
| 管理员      | 后台运营人员    | 第二版：图书上架/下架（可选改库存）；种子账号 `admin` |

### 2.3 业务范围

#### 2.3.1 范围内（In Scope）

1. 用户注册、登录、获取当前用户信息。
2. 图书分类、图书列表、图书详情。
3. 购物车增删改查。
4. 创建订单、查看我的订单、订单详情。
5. 下单时扣减库存。
6. 下单成功后产生站内通知，用户可查看通知列表。
7. 前端页面：首页/图书、详情、登录注册、购物车、订单、通知、查书客服。
8. API 网关统一入口。
9. 下单扣库存与写订单用令牌回补保持同一业务结果。第五期的 Seata 全局事务已撤回。客服只能查书；日志带追踪号。
10. 第六期：管理员可新增图书；MongoDB 保存梗概等内容；外部书目查百度百科；没有梗概时用智谱补写。前端为 Vite、Vue Router、Pinia、Axios、Element Plus、TypeScript、ECharts 和 Day.js。
11. 第七期：管理员进货对照。一次提交的书名默认最多 20 本，用 JDK 21 虚拟线程同时查本店和百度百科。某一本百科连不上不影响其余书。下单扣库存仍不使用虚拟线程。对照上限、百科超时和列表缓存时间放在 Nacos，发布后不用重启图书服务。
12. 第八期：网关登录/注册用令牌桶限流；图书列表用 Sentinel 匀速排队（漏桶式）；下单与客服提问用 QPS 直接拒绝；百科调用异常比例熔断。规则本地 JSON，不部署 Dashboard。不对扣库存 Feign 做熔断。超限返回 `42901`。

#### 2.3.2 范围外（Out of Scope）

以下内容明确不在第一版：

- 真实支付（微信/支付宝）、退款、发票
- 物流、收货地址管理、快递轨迹
- 优惠券、积分、会员等级
- 秒杀、拼团、评价/评分体系
- 后台管理端（图书/订单运营后台）
- 搜索引擎（Elasticsearch）、推荐算法
- Kubernetes 以外的服务网格、全链路复杂监控（第五期只要求日志里的追踪号，本机和 Compose 可导出到 Zipkin）
- 短信/邮件真实外发

### 2.4 系统上下文

外部使用者只有浏览器中的前端应用。前端只访问网关；网关转发到各业务服务。

```text
浏览器(Vue)
    │
    ▼
API 网关 (:8080)
    ├── 用户服务 (:8081)
    ├── 图书服务 (:8082)
    ├── 订单服务 (:8083) ──内部调用──► 图书服务
    ├── 通知服务 (:8084)
    └── 客服服务 (:8085) ──只读查书──► 图书服务
```

### 2.5 假设与依赖

1. 开发与演示环境可运行 JDK 21、Node.js、Maven，并可通过 Docker 启动 PostgreSQL。
2. 使用 PostgreSQL 16。客服使用 `bookmall_assistant`。`bookmall_seata` 可以留在库里，服务不再连接。每个服务使用独立账号，只授权访问自己的库。
3. 第二版站内通知经 RabbitMQ 异步写入；订单服务只负责投递，通知服务消费并按 biz_key 幂等入库。内部 HTTP 补发接口可保留，不对公网暴露。
4. 第二版图书服务使用 Redis 缓存分类与在售列表（短 TTL）；管理端改书或库存变化后失效缓存。Redis 不可用时降级读库。
5. 所有受保护接口使用同一套 JWT 密钥与鉴权规则。

## 3. 功能需求

### 3.1 用例总览

| 编号    | 用例             | 主要角色  | 优先级 |
| ----- | -------------- | ----- | --- |
| UC-01 | 注册账号           | 游客    | P0  |
| UC-02 | 登录             | 游客    | P0  |
| UC-03 | 查看当前用户         | 读者    | P0  |
| UC-04 | 浏览图书列表         | 游客/读者 | P0  |
| UC-05 | 查看图书详情         | 游客/读者 | P0  |
| UC-06 | 加入购物车          | 读者    | P0  |
| UC-07 | 修改购物车数量 / 删除条目 | 读者    | P0  |
| UC-08 | 查看购物车          | 读者    | P0  |
| UC-09 | 提交订单           | 读者    | P0  |
| UC-10 | 查看我的订单 / 订单详情  | 读者    | P0  |
| UC-11 | 查看站内通知         | 读者    | P1  |
| UC-12 | 按分类筛选图书        | 游客/读者 | P1  |
| UC-13 | 向客服查书           | 读者    | P0  |

### 3.2 用户与认证

#### FR-U-01 注册

- 输入：用户名、密码、昵称（可选）。
- 规则：
  - 用户名 3–20 字符，系统内唯一；
  - 密码 6–32 字符，服务端加密存储，禁止明文落库；
  - 昵称为空时默认等于用户名。
- 成功：返回 JWT 与用户基本信息，视为自动登录。
- 失败：用户名已存在、参数不合法时返回明确错误信息。

#### FR-U-02 登录

- 输入：用户名、密码。
- 成功：返回 JWT 与用户基本信息。
- 失败：用户名或密码错误时，不区分具体哪一项错误（统一提示）。

#### FR-U-03 当前用户

- 需要登录。
- 返回：用户 ID、用户名、昵称。
- Token 无效或过期：返回 401。

#### FR-U-04 鉴权规则

- 公开接口：注册、登录、图书列表、图书详情、分类列表。
- 其余业务接口：必须携带 `Authorization: Bearer <token>`。
- 网关负责对外鉴权；业务服务也应具备防护能力（防止绕过网关直连）。

### 3.3 图书与分类

#### FR-B-01 分类列表

- 返回全部图书分类（如文学、技术、生活等）。
- 第一版分类由初始化数据提供。

#### FR-B-02 图书列表

- 支持分页。
- 可选按分类筛选。
- 可选按书名关键字模糊查询（P1）。
- 列表字段至少包含：图书 ID、书名、作者、封面、价格、库存、分类名。

#### FR-B-03 图书详情

- 按图书 ID 查询。
- 不存在时返回 404 业务错误。
- 详情字段在列表字段基础上增加：简介、ISBN（可选）、上架状态。有内容文档时再加梗概、目录、摘录、标签、作者简介和来源。MongoDB 不可用时这些内容字段省略，价格和库存仍返回。

#### FR-B-04 库存扣减（内部）

- 提供仅供内部调用的库存扣减接口。
- 输入：图书 ID、扣减数量。
- 规则：库存不足则失败，不得扣成负数。
- 成功后返回最新库存。

#### FR-B-05 初始化数据

- 系统首次启动应自动准备：
  - 不少于 3 个分类；
  - 不少于 8 本示例图书；
  - 每本图书库存 > 0。

### 3.4 购物车

#### FR-C-01 加入购物车

- 需要登录。
- 输入：图书 ID、数量（默认 1）。
- 规则：
  - 图书必须存在且可售；
  - 数量必须为正整数；
  - 同一用户同一图书合并数量，不新增重复行。
- 数量合计不得超过当前库存（可在加购或下单时校验；第一版要求**下单时强校验**，加购时建议校验）。

#### FR-C-02 修改数量

- 需要登录。
- 只能修改本人购物车条目。
- 数量改为 0 时视为删除该条目。

#### FR-C-03 删除条目

- 需要登录。
- 只能删除本人购物车条目。

#### FR-C-04 查看购物车

- 需要登录。
- 返回条目列表：图书信息快照（至少书名、单价、封面）、数量、小计。
- 同时返回应付合计金额。

### 3.5 订单

#### FR-O-01 创建订单

- 需要登录。
- 输入：购物车中勾选的条目；省略勾选时结算全部购物车。空的勾选列表拒绝下单。
- 处理流程：
  1. 校验购物车非空；
  2. 校验每本图书库存充足；
  3. 扣减库存；
  4. 生成订单与订单明细；
  5. 清空已结算购物车条目；
  6. 触发下单成功通知。
- 订单状态：
  - `1`：待支付（PENDING_PAY，下单时已扣库存）；
  - `2`：已取消（CANCELLED）；
  - `3`：已支付（PAID，模拟支付，不对接微信或支付宝）。
- 第三版把迁移前已存在的 `status = 1` 改为 `3`，避免旧演示订单全部变成待支付。
- 失败时：不得产生“库存已扣但无订单”的脏状态。写订单失败或中途扣减失败时，按已尝试的令牌回补库存。回补失败返回服务器内部错误，占用记录保留，下次该用户下单继续回补。库存不足时整单失败。
- 下单成功通知和支付超时消息在订单写入成功之后发出。消息失败不回滚订单。
- 取消订单和支付超时仍按原路径还库存。

#### FR-O-02 我的订单列表

- 需要登录。
- 仅返回当前用户订单。
- 支持按创建时间倒序。
- 列表字段：订单号、总金额、状态、创建时间、商品件数。

#### FR-O-03 订单详情

- 需要登录。
- 只能查看本人订单。
- 包含订单头信息与明细列表（书名、单价、数量、小计）。

#### FR-O-04 订单号规则

- 订单号全局唯一，可读性优先（如时间戳 + 随机串），不要求符合外部支付规范。

#### FR-O-05 取消订单（第二版）

- 需要登录；仅本人可取消。
- 仅 `PENDING_PAY` 可取消；成功后状态为 `CANCELLED`，并按明细数量加回库存。已支付不可取消。
- 可投递取消站内通知（`biz_key=ORDER_CANCELLED:{订单号}`）。
- 已取消订单不可再次取消；他人订单或不存在按 404。

#### FR-O-06 模拟支付（第三版）

- 需要登录；仅本人可支付。
- 仅 `PENDING_PAY` 可支付；成功后状态为 `PAID`，不再扣减或加回库存。
- 不调用微信、支付宝或任何外部收银台。页面上的「支付」只改订单状态。
- 重复支付、取消已支付订单返回 40008。
- 可投递支付通知（`biz_key=ORDER_PAID:{订单号}`）。

#### FR-O-07 待支付超时关单（第三版）

- 下单成功后向 RabbitMQ 延迟队列投递一条消息，过期时间默认 15 分钟，开发环境可配成 1 分钟。
- 消息过期后经死信进入超时队列。消费者看到订单仍是 `PENDING_PAY` 时，按取消订单还库存。
- 已支付或已取消的订单收到超时消息时直接确认，不再还库存。
- 投递超时消息失败不回滚订单。

### 3.6 通知

#### FR-N-01 下单成功通知

- 订单创建成功后，为对应用户生成一条站内通知（第二版经 RabbitMQ，最终一致）。
- 通知内容示例：`您的订单 {订单号} 已创建成功，合计 ¥{金额}`。
- 幂等键：`ORDER_CREATED:{订单号}`。

#### FR-N-04 通知死信（第三版）

- 参数不合法的通知消息记日志后确认，不进入死信队列。
- 数据库等瞬时失败最多重试 3 次，仍失败则进入死信队列 `bookmall.notification.create.dlq`，不再无限重新入队。

#### FR-N-02 通知列表

- 需要登录。
- 仅返回当前用户通知，按时间倒序。
- 字段：通知 ID、标题/内容、是否已读、创建时间。

#### FR-N-03 标记已读（P1）

- 支持单条标记已读；可选支持全部已读。

### 3.7 查书客服（第五期）

#### FR-A-01 提问

- 需要登录。
- 用 LangChain4j 调用智谱的 OpenAI 兼容接口，模型默认 `glm-4.7`。只配置一个模型，不自动切换。
- 回答用 SSE 流式返回。用户消息先入库；流结束写入客服回复；连接中断则保存已生成的部分。
- 每次只把最近 10 轮对话发给模型。提示词要求简短，并且只能根据工具结果回答。
- 工具只读：按书名、作者、分类查书，并读取价格、库存、`ON_SALE` / `OFF_SALE`。能看到下架书。不能下单、支付或取消。
- 开发、测试、生产都一样：没密钥时 HTTP 503、`code` 50301、message「客服未配置」。不写入这条提问，也不提供模拟回复。
- 密钥只在服务端，不进前端，不进日志。

#### FR-A-02 历史

- 需要登录。
- 一个用户一条时间线。只返回当前用户的消息。
- 分页。第 1 页是最近的消息，页内按时间从早到晚。

### 3.8 前端功能需求

#### FR-F-01 页面清单

| 页面    | 说明           |
| ----- | ------------ |
| 首页/书城 | 分类筛选 + 图书列表  |
| 图书详情  | 展示详情，支持加入购物车 |
| 登录/注册 | 表单提交，成功后跳转   |
| 购物车   | 数量修改、删除、去结算  |
| 我的订单  | 订单列表与详情；待支付可支付或取消 |
| 消息中心  | 通知列表         |
| 客服     | 查书对话，流式回答，只看本人历史 |
| 管理     | 管理员新增图书、编辑梗概、查百科并引进、生成梗概；上架/下架和改库存仍可用。订单页有状态柱状图 |

#### FR-F-02 交互要求

1. 未登录访问受保护操作时，引导至登录页。
2. Token 存于前端本地（如 localStorage），请求自动携带。
3. 接口错误需有可读提示（如库存不足、用户名已存在）。
4. 桌面端优先；移动端基本可用即可（不要求复杂自适应设计系统）。

#### FR-F-03 视觉基调（建议）

- 品牌名「纸间书店」在首屏应有明确识别。
- 风格偏阅读/书店氛围，避免常见 AI 模板感（如紫白渐变堆砌）。
- 第一版以功能完整优先，视觉可后续迭代。

### 4.2 外部 API（经网关）

> 下列为逻辑接口清单，具体路径可在详细设计中微调，但语义不得偏离。

#### 用户服务

| 方法   | 路径                    | 鉴权 | 说明   |
| ---- | --------------------- | -- | ---- |
| POST | `/api/users/register` | 否  | 注册   |
| POST | `/api/users/login`    | 否  | 登录   |

#### 图书服务

| 方法  | 路径                | 鉴权 | 说明          |
| --- | ----------------- | -- | ----------- |
| GET | `/api/categories` | 否  | 分类列表        |
| GET | `/api/books`      | 否  | 图书列表（分页/筛选） |

### 4.4 统一响应约定

```json
{
  "code": 0,
  "message": "ok",
  "data": {}
}
```

- `code = 0` 表示成功。
- 业务失败：`code` 非 0，`message` 为可读中文。
- HTTP 状态码建议：
  - 400 参数/业务可预期错误；
  - 401 未登录或 Token 失效；
  - 403 无权限（如查看他人订单）；
  - 404 资源不存在；
  - 500 未预期错误。

### 5.6 数据隔离原则

- 使用 PostgreSQL。库与服务对应：`bookmall_user`、`bookmall_book`、`bookmall_order`、`bookmall_notification`、`bookmall_assistant`。`bookmall_seata` 不再被服务使用。
- 每个服务使用独立账号，只授权自己的库。禁止跨服务直接访问对方数据库。
- 主键使用 `bigint generated by default as identity`。
- 时间字段使用 `timestamptz`，应用按 UTC 写入。
- 订单明细中的书名、单价必须落快照，避免图书信息变更影响历史订单展示。

## 6. 非功能需求

### 6.1 可用性与体验

- 本地一键或少量命令可启动全部服务与前端。
- 主流程操作反馈时间在本地环境下通常 < 2 秒。
- 关键错误信息对用户可读，不直接暴露堆栈。

### 6.2 安全性

- 密码加密存储（如 BCrypt）。
- JWT 密钥可配置，长度满足算法要求。
- 所有写操作与用户私有读操作必须鉴权。
- 用户只能访问自己的购物车、订单、通知和客服对话。
- 一次下单或一次提问，网关和下游服务的日志带同一个 `traceId`。生产默认只打日志；设置了 Zipkin 地址才导出。本机和 Compose 提供 Zipkin。

### 6.3 可维护性

- 多模块 Maven 工程，模块边界清晰。
- 统一响应体与统一异常处理。
- 提供 README：如何启动、如何演示、默认账号/种子数据说明。

### 6.4 可测试性

- 至少覆盖：
  - 注册/登录成功与失败；
  - 库存不足下单失败；
  - 下单成功后订单可见、购物车已清空、通知已生成。
- 可用接口测试或集成测试完成，不强制 UI 自动化。

### 6.5 兼容性

- 后端：JDK 21。
- 前端：现代 Chromium 内核浏览器（Chrome / Edge 近两个大版本）。
- 第一版不要求 IE 或老旧移动浏览器。

### 6.6 性能（学习项目级别）

- 不做压测达标要求。
- 图书列表分页默认每页 10 条，避免一次返回过大。

```text

## 9. 分期计划

### 阶段 A：骨架与认证（建议先做）

- 多模块工程与网关路由
- 用户注册/登录/JWT
- 前端登录注册页可连通

### 阶段 B：书城浏览

- 分类与图书数据
- 图书列表/详情 API
- 前端书城与详情页

### 阶段 C：购物车与订单闭环

- 购物车 CRUD
- 下单与扣库存
- 订单列表/详情
- 前端购物车与订单页

### 阶段 D：通知与打磨

- 下单通知
- 消息中心页
- 基础测试、README、演示脚本

### 阶段 E：第二版增强（已纳入当前范围）

- Redis 缓存分类与图书列表
- RabbitMQ 异步通知（幂等 biz_key）
- 订单取消（待支付 → 已取消，还库存）
- 管理端图书上架/下架
- Docker Compose 与 Kubernetes 本地部署

### 阶段 F：第三版（已纳入当前范围）

- 购物车勾选结算
- 模拟支付（待支付 → 已支付），不做真实支付、不做微信/支付宝登录
- 待支付超时自动取消并还库存
- 通知消费有限次重试后进入死信队列

### 阶段 G：第四版（已纳入当前范围）

- 读者按 `PENDING_PAY` / `PAID` / `CANCELLED` 筛选自己的订单。
- 管理员分页查看全部订单和详情，不能代付或代取消。
- 管理员查看通知死信和支付超时死信，可重投最早一条或丢弃。
- 订单访问图书改为 OpenFeign，超时与 40006 / 40400 映射保持不变。
- 本地与 Docker Compose 使用 Nacos；生产固定地址，Kubernetes 仍用 Service DNS。
- `book.on_sale`、`stock_change.deducted`、`notification.read_flag` 改为 boolean。用户角色和订单状态仍用数字。

### 阶段 H：第六期（已纳入当前范围）

- 管理员新增图书，`book` 增加可空 `isbn`。
- MongoDB 保存梗概、目录、摘录、标签和作者简介。价格、库存、上下架仍在 `book`。
- 外部书目查百度百科名片。没有词条时成功且 data 为空。连不上返回 50302。引进时由管理员填写分类、价格、库存和上下架。百科没有摘要时，客服用智谱补一段并标明本店未上架；已有百科或管理员梗概不被覆盖。
- 没有梗概时客服用已配置的智谱写一份，`source` 为 `ZHIPU`。管理员或百科已有正文不被覆盖。
- 前端改为 Vite、Vue Router、Pinia、Axios、Element Plus、TypeScript。时间用 Day.js。管理订单页用 ECharts 按状态画柱状图，数据来自现有订单列表。客服流式回答仍用 `fetch`。

### 阶段 I：第七期（已纳入当前范围）

- 下单不再使用 Seata。扣库存和写订单失败时按令牌回补。
- 管理员在图书管理页提交书名清单，做进货对照。
- 每本书名使用一个 JDK 21 虚拟线程，同时查询本店图书和百度百科。默认同时最多 4 个查询，整批最多 20 秒。
- 本店结果带价格、库存和上下架。百科结果不带价格、库存和上下架。
- 某一本百科连不上时，这一行标记为暂时不可用，其余书仍返回。
- 下单和扣库存不改到虚拟线程上。
- 进货对照上限、百科超时和列表缓存时间由 Nacos 配置 `bookmall-catalog.yaml` 热刷新。

### 阶段 J：第八期（已纳入当前范围）

- 网关对 `POST /api/users/login`、`POST /api/users/register` 使用 Guava 令牌桶限流，允许短突发，平均超速返回 HTTP 429、`code` 42901。
- 网关对 `GET /api/books`（精确路径）使用 Sentinel 匀速排队（`controlBehavior=2`，接近漏桶），排队超时同样 42901。图书详情不限流。
- 订单 `order-create`、客服 `assistant-ask` 使用 Sentinel 默认 QPS 直接拒绝；客服限流发生在写出 SSE 之前。
- 百科 `baike-lookup` 异常比例熔断；熔断打开与连不上一样返回 50302。进货对照仍可按本标 `UNAVAILABLE`。
- 规则从各模块 `classpath:sentinel/*.json` 加载，不启 Sentinel Dashboard，不接 Nacos 规则源。
- 不对 `deduct` / `restore` 与订单→图书 Feign 扣库存做熔断或假成功降级。
